# Continuing a routing pass after a failed net

Set `sequential.continue_after_routing_failure` to `true` in an adaptive configuration, or `continue_after_routing_failure` in a standalone sequential configuration, to attempt later nets after an ordinary routing failure. It defaults to false. Keep the existing physical rules, portfolio and repair bounds; the option changes traversal only.

A sweep attempts each original-order net at most once, up to `maximum_connections`. A failed net remains pending while later nets may commit. Only an attempted, typed grid-disconnected or search-budget-exhausted failure permits continuation. Skipped-only alternatives, unsuccessful repair receipts, adapter errors and native admission failures stop that sweep. Every committed route still passes the original native gate and restores every displaced net. The top-level repair allowance applies to the entire pass and is not reset after a failed net.

The adaptive coordinator accepts the option and learns from attempted failures, later successes and the still-unattempted tail separately. Each later pass starts from the independently verified cold source. A sweep-local halt does not forbid the coordinator from trying another bounded cold policy or order; native admission and incumbent selection remain unchanged.

Enabled sequential reports use schema 9. `steps` records attempted original-order identities, so admitted steps can be separated by failed steps. `completed_connections` is a count, not an index into a contiguous committed prefix. The `sweep` field partitions electrical identities into `completed`, `failed` and `unattempted`, records the cumulative repair count, and checks predicted open items against the native retained board at every checkpoint. Coincident front/back pads retain their distinct electrical groups. Demand is removed only for nets that actually committed.

A bound can leave both failed and unattempted nets. An exhausted sweep with any failed net reports `routing_failed`, even if the last attempted net succeeded. `halted_on_unclassified_failure` identifies a conservative sweep-local stop. The default continues to emit legacy schema 8 and preserve its prefix behavior and serialization.

External checkpoint resume currently rejects sparse reports, and legacy order search rejects this option because it assumes its final step is the failed net. Adaptive routing is supported. The existing sequential audit checks schema-9 sparse inventories and admission history; it retains the older prefix assertions for older schemas.

The clean H/V/L mechanism verifies the intended behavior: H blocks V; default routing stops with H only, while a sweep additionally routes independent L. An adaptive observed retry then tries V,H,L and completes all three. The sweep's copper matches the earlier automatic-resume prototype exactly. ECC83's completed-routing control has identical off/on committed board hashes, route work and native findings; its two inherited silkscreen findings still prevent full clean-board credit. Unit controls cover electrical open accounting, failure classification, failed-demand retention, cumulative repair receipts and sparse adaptive learning. Malformed and inconsistent native receipts are rejected by the existing audit.

The fresh automatic-resume Interf prototype reached 85/110 nets and 101 native open items, versus 55/110 and 143 opens when stopping at the first failure. It still did not complete the board. Repeated resume preparation consumed about 380 seconds outside new route-step timers, motivating the in-process implementation. The subsequent matched fresh four-pass adaptive comparison used one frozen executable, unchanged native rules and 1800 seconds per arm: default retained 55/110 with 143 opens, while the in-process sweep retained 94/110 with 88 opens and attempted every net. Both timed out incomplete; all retained and interrupted-pass audits passed. Initial shared route work/copper was identical. Details are recorded in the [fresh whole-board evaluation](2026-09-09-fresh-whole-board-evaluation.md). The option remains experimental rather than a default capability claim.
