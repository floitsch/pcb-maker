# Routing through via-only keepouts

This is a regression for autonomous native routing, generated by
[`tests/kicad_via_keepout.rs`](../../../tests/kicad_via_keepout.rs) from the
existing mandatory-layer-transition problem and template.

The board has two fixed pads on opposite copper layers. Four native rule areas
allow tracks but prohibit vias everywhere except a 2 mm square window. The
program must choose a via location in that window and complete the connection.
The test does not supply a route or via coordinates to the router.

## Diagnosed limitation and implementation

The old KiCad adapter lowered only rule areas that prohibited tracks. It ignored
via-only restrictions, chose its ordinary finish-side via, and stopped when
native admission rejected that candidate. Increasing search effort on the same
incorrect obstacle model would not make that candidate legal.

The adapter now retains independent track/via blocking permissions. The grid's
planar occupancy and edge checks use track permissions, while via occupancy and
candidate via checks use via permissions. Local planar rerouting, shortening,
blocker attribution, and continuous trace-obstacle selection also respect track
permissions. Existing foreign copper and pads block both kinds of copper.

This is an algorithmic input-model correction. Native acceptance policy and the
router's strategy selection remain authoritative; no agent chooses runtime edits.

## Retained before/after result

On the identical native source and routing configuration:

| Measurement | Unchanged release control | Repaired program |
| --- | --- | --- |
| Completed connections | 0/1 | 1/1 |
| First candidate via, mm | (34.95, 17.95) | (25.2, 17.95) |
| Native design findings | 1 `items_not_allowed` | 0 |
| Remaining opens | 0 in the rejected candidate | 0 |
| Native admission | Rejected | Accepted on first candidate |
| A* expansions | 82 | 123 |

The accepted candidate has zero ERC, DRC, parity, and unconnected-item findings.
The source board remains byte-identical. The via coordinates above are observed
outputs, not constraints fed to the search. The comparison establishes capability
on this mechanism, not a wall-clock speedup; the control is a release binary and
the repaired integration test uses a debug build.

The [comparison](../../../build/routing-improvements/via-only-keepout-2026-09-07/comparison.json)
retains native admissions, with complete generated projects and route artifacts
alongside it. This regression does not add a new Freerouting competitive score.

## Reproduction

```
cargo test -p pcb-kicad --lib rule_area_tests
cargo test --test kicad_via_keepout
```

Set `PCB_MAKER_KEEP_TEST_ARTIFACTS=1` for the second command to retain its generated
project and print the directory. Native integration requires `kicad-cli`; it
reports a skip if KiCad is unavailable. The unit tests run without KiCad and
cover all four track/via permission combinations, an allowed via window, and
an impossible control with the window completely closed.

Validation on 2026-09-07: 86 `pcb-kicad` library tests, 9 `pcb-grid-router`
library tests, and the native autonomous via-window integration test pass.
