# Automatic recovery from search-budget exhaustion

This experiment turns the earlier manual harmonic-placement diagnosis into a
conditional action in the native connection-insertion program. The router
emits structured search failures; a configured conditional entry activates
only after budget exhaustion and only when no earlier route candidate exists.
It does not classify failures by reading their text.

The policy remains opt-in. Reusable insertion configurations preserve the
existing physical rules and two-million A* budget:

- `experiments/configs/dual-esp32-blocked-adaptive-search.json`
- `experiments/configs/dual-esp32-open-adaptive-search.json`

Both add one conditional obstacle-distance entry to the corresponding ordinary
router configuration. They preserve the original baseline benchmark files.
The conditional entry is bounded by the existing candidate cap and passes the
same native admission gate. Duplicate routing configurations are still skipped.
An existing generated candidate suppresses this trigger even if it later
fails native admission; native-rejection recovery is a separate concern.

```sh
cargo build --release --offline
python3 experiments/budget-trigger/run.py build/my-budget-trigger-replay
```

The output must be fresh. The script copies and hashes the executable, records
subprocess outcomes, audits decisions and native results, and automatically
creates `index.html` with board renderings. It uses retained dense-probe
parents from `build/placement-dense-prefix19-2026-09-07/`.

The positive case starts at harmonic/blocked prefix 16 and progresses to 19.
Guidance activates on the first failed route and skips the next two successful
ordinary routes. The negative case starts at junction/blocked prefix seven;
exhaustive grid disconnection does not activate guidance, and rollback remains
exact. This experiment intentionally disables rip-up to isolate the trigger.
The earlier independent rip-up experiment repairs that negative case.

All accepted and rollback boards have native verification and automatic SVG
previews. A* work, reachability work and guidance preprocessing are separately
recorded. No CPU speed claim is inferred from state counts or concurrent wall
times. The conservative profile is natively exercised here; the open-profile
configuration is generated by the same rule-preserving transformation, not a
new native open-profile measurement in this experiment.
